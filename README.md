# 🔥 VCita

单用户的间隔重复背词 Web App。纯静态站点，数据存在浏览器本地（IndexedDB），
可同步到你自己的**私有** GitHub 数据仓库的 `VCita/` 目录。同步机制与 TimeEncre 相同，两个 app 可以共用一个数据仓库。

## 功能

- **笔记 → 卡片 → 复习日志**三层结构：内容只写一次，一条笔记按需生成认读、产出、挖空三种卡
- **核心 / 中频**两层：核心词默认认读 + 产出两张卡，中频只认读；编辑器里实时预览三种卡
- **SM-2 调度**：四级评分、学习步骤、重学步骤、每日新卡上限、复习优先、同一条笔记的卡当天只出一张
- **顽固卡**：遗忘达到阈值（默认 8 次）自动暂停，进入"待改造"
- **输入即翻译**：回车立即入库，后台用 Google 翻译填两种目标语言，可以连续输入
- **卡片旋转**和**题面切换**：每张卡可以单独旋转题面；复习页顶部可以整体切换用哪种语言出题
- **撤销 + 全键盘操作**
- **统计**：保持率（年轻 / 成熟分开）、顽固卡、未来 30 天到期量、产出使用次数
- **分拣**：词库里按已稳定、待改造、待补句子、核心、待补产出筛选，配合批量操作
- **批量导入**：每行一条，`句子（含 {{…}}）| 中文 | 英语 | 出处 | 主题`
- **8 个主题**：TRAVAIL · SOCIÉTÉ · TECHNOLOGIE · ENVIRONNEMENT · MÉDIAS · ÉDUCATION · SANTÉ · GÉNÉRAL
- **GitHub 同步**：每次同步一个提交，多设备按"较新者胜出"合并；没有改动不产生提交
- 发音走 Google TTS；部署在 CF Pages / Vercel 时随站点发布一个同源代理，不可用时退回浏览器自带语音

## 本地运行

```bash
npm install
npm run dev      # 开发
npm test         # 单元测试
npm run build    # 产物在 dist/
```

## 部署

这是需要**构建**的 Vite 项目：源码（`src/*.tsx`）不能直接发布，必须先 `npm run build`，再发布产物目录 `dist/`。
构建命令或输出目录留空，平台会把源码原样发布，页面是空白，Console 里报
`Failed to load module script ... MIME type of "application/octet-stream"`。

纯静态，不需要任何环境变量。`base: './'` + hash 路由，部署在根路径或子路径都能用。
`.node-version` 指定了 Node 22（Vite 8 需要 Node 20.19+ / 22.12+），两个平台都会读取。

两个平台都会在你推送到 `master` 时自动重新部署。

### Cloudflare Pages

1. Dashboard → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**，选择本仓库
2. **Set up builds and deployments** 页面：

   | 项目 | 填写 |
   |---|---|
   | Production branch | `master` |
   | Framework preset | `None`（或 `Vite`，效果一样，下面两项以手填为准） |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory (advanced) | 留空。**只有**项目文件不在仓库根目录、而是在子目录（比如 `vcita/`）时，填这个子目录 |
   | Environment variables | 不需要。如果构建日志提示 Node 版本过低，加 `NODE_VERSION` = `22` |

3. **Save and Deploy**。构建日志里应该能看到 `vite build` 和 `✓ built in …`
4. 打开 `https://<项目名>.pages.dev`，应该看到"第一次打开"的三选一页面

`functions/api/tts.js` 会自动发布为 Pages Function（发音代理），不需要额外设置。

**已经用错误配置部署过**：项目 → **Settings** → **Builds & deployments** → **Build configuration** → **Edit**，按上表改好，
然后到 **Deployments**，对最新一次点 **⋯ → Retry deployment**。

### Vercel

1. Dashboard → **Add New…** → **Project** → 导入本仓库
2. **Configure Project** 页面：

   | 项目 | 填写 |
   |---|---|
   | Framework Preset | `Vite`（一般会自动识别） |
   | Root Directory | 仓库根目录；项目在子目录时选那个子目录 |
   | Build Command | `npm run build`（展开 Build and Output Settings 确认） |
   | Output Directory | `dist` |
   | Install Command | 默认（`npm install`） |
   | Environment Variables | 不需要 |

3. **Deploy**，完成后打开 `https://<项目名>.vercel.app`

`api/tts.js` 会自动发布为 Edge Function（发音代理）。
Node 版本：项目 → **Settings** → **General** → **Node.js Version** 选 22.x（`.node-version` 通常已生效，这里确认一下）。

**改配置后重新部署**：项目 → **Settings** → **Build and Deployment** 改好后，到 **Deployments**，对最新一次点 **⋯ → Redeploy**。

两个平台用的是同一份构建产物、同一个数据仓库，任选一个网址使用即可；另一个作为备用。
注意浏览器数据按**网址**隔离：`*.pages.dev` 和 `*.vercel.app` 是两份独立的本地数据，换网址使用时选"从 GitHub 数据仓库恢复"即可。

部署出去的站点只是一个空壳：数据只在你自己的浏览器和私有数据仓库里，别人打开网址看到的是空界面。

## 第一次打开

三选一：

| 选项 | 什么时候用 |
|---|---|
| **从 GitHub 数据仓库恢复** | 已经在别的设备上用过。在设置里连接同一个仓库，保存后会自动同步一次，把数据拉下来。**不要**先导入备份，否则同一批词会变成两份 |
| **导入旧版备份** | 从服务器版 VCita 迁移过来（见下文） |
| **从空白开始** | 全新使用 |

## 连接 GitHub 数据仓库

1. 建一个**私有**仓库（公开仓库会被拒绝），或者直接用 TimeEncre 的数据仓库。VCita 只读写其中的数据目录（默认 `VCita/`）。
2. 生成 **fine-grained personal access token**：Repository access 只选这个仓库，Permissions 只开 `Contents: Read and write`，设置过期时间。不要用 classic token。
3. 打开 app → 设置 → GitHub 同步，填仓库（`owner/repo` 或完整网址）、数据目录和令牌，点"检查并保存"。
4. 打开"自动同步"：打开 app 时、停止改动 3 分钟后、切到后台时、一轮复习结束时各同步一次。

⚠️ fine-grained token 只能限定到仓库、不能限定到目录：和 TimeEncre 共用仓库时，两个 app 的令牌都能读写对方的数据。
令牌保存在各设备浏览器本地，不会随备份导出；"清空本地数据"会保留它。

**一次同步做了什么**（请求数与文件数无关，除了第 2 步）：

1. 读远端分支头和数据目录的文件列表（2–3 个请求）
2. 下载远端变过的文件：**8 个并发**。日常同步一般只有 1–3 个文件；新设备第一次同步要下载全部文件（几十个），几秒完成
3. 合并进本地，计算本地变过的文件
4. 把所有变过的文件放进**一个提交**推上去（3 个请求：建树、建提交、移动分支）。没有变化就不提交

本地还没有任何数据时不会推送任何东西，所以新设备连接后不会往仓库里写一个空牌组。

## 从旧版（服务器版）迁移

1. 在旧版的"备份"页点 Export，得到 `vocabforge-YYYY-MM-DD.json`
2. 打开新版 → "导入旧版备份" → 选择这个文件
   - 旧版有多个用户时，选择要导入的那一个（新版是单用户）
   - 旧标签逐个映射到 8 个主题（已按名称自动猜好，例如 Police et Justice → SOCIÉTÉ、médecine → SANTÉ）
3. 设置 → 连接 GitHub → 立即同步，确认仓库里出现 `VCita/` 目录
4. 其他设备选"从 GitHub 数据仓库恢复"，**不要**再导入一次
5. 核对卡片数和复习进度

迁移规则：每张旧卡 → 一条笔记 + 一张认读卡。调度字段（状态、到期日、间隔、ease、复习次数、遗忘次数）原样保留，
`reviewHistory` 转成复习日志，旧卡对象原样存进笔记的 `legacy` 字段。同一份备份重复导入不会产生任何变化，也不会覆盖之后的复习进度。
旧卡没有例句，复习时正面显示单词，标"待补句子"。

## 复习算法（SM-2）

| 评分 | 新卡 / 学习中 | 复习卡 |
|---|---|---|
| 1 忘了 | 回到第一个学习步骤（10 分钟） | 遗忘 +1，倍率 −0.2，进入重学（10 分钟），之后间隔 = 原间隔 × 0.5（最少 1 天） |
| 2 困难 | 重复当前步骤 | 间隔 × 1.2，倍率 −0.15 |
| 3 良好 | 下一个学习步骤；走完后毕业，间隔 3 天 | 间隔 × 倍率 |
| 4 容易 | 直接毕业，间隔 4 天 | 间隔 × 倍率 × 1.3，倍率 +0.15 |

- 倍率（ease）初始 2.5，最低 1.3，越低说明越难记
- 1 天以上的步骤和所有复习间隔都对齐到**学习日**开始（默认凌晨 4 点切换），凌晨复习仍算前一天
- 间隔加 ±5% 随机扰动，避免同一天加的卡永远挤在同一天到期（可关）
- 出题顺序：到期的学习卡 → 到期的复习卡 → 新卡（有到期复习卡时不出新卡）；同一条笔记的卡当天只出一张；没有别的卡时，20 分钟内到期的学习卡提前出

所有参数都在 **设置 → 复习** 里改，随 GitHub 同步到其他设备。

## 快捷键（复习页）

| 键 | 作用 |
|---|---|
| `空格` / `回车` | 显示答案；已显示时 = 良好 |
| `1` – `4` | 评分 |
| `U` | 撤销上一次评分 |
| `S` | 跳过（本轮不再出现） |
| `P` | 暂停这张卡（词库"已暂停"里可恢复） |
| `E` | 编辑这条笔记 |
| `?` | 说明 |

快捷键在捕获阶段处理，不会被"空格 = 播放/暂停"类浏览器扩展抢走；输入框和弹窗里不生效。

## 数据格式

全部是 JSON。时间为带时区的 ISO 8601（毫秒），id 为 UUIDv7（迁移来的数据沿用旧 id 加前缀）。
每个文件都有 `schemaVersion`（当前为 2），读取时经 `src/schema/index.ts` 的迁移链升级到当前版本；
遇到比程序新的版本会拒绝写入。结构定义见 `src/schema/v2.ts`。

数据仓库中的布局：

```
VCita/
  profile.json              牌组、设置
  notes/2026-09.json        笔记，按创建月份
  cards/2026-09.json        卡片调度状态，按所属笔记的创建月份
  logs/2026-10/02.json      复习日志，按学习日
```

复习日志按天分文件，所以每次同步只会改当天这一个日志文件。

**合并规则**：

| 数据 | 规则 |
|---|---|
| 牌组、设置、笔记、卡片 | 按 `updatedAt` 较新者胜出；删除以墓碑（`deleted: true`）传播 |
| 复习日志 | 只增不改，按 id 取并集；撤销时打墓碑，不会被别的设备带回来 |

两台设备离线复习同一张卡：卡片状态以后复习的为准，两条日志都保留。

## 上线后的收尾清单

0. **把误提交的 Vite 缓存移出仓库**：`.vite/` 已加进 `.gitignore`，再执行一次 `git rm -r --cached .vite` 并提交

确认新版数据完整、两台设备同步正常之后：

1. **停掉旧服务**：`pm2 delete <id>`，然后 `pm2 save`。同名进程有多个时按 id 删
2. **删掉 Caddy 里的 `/vocab-forge` 反向代理配置**，重载 Caddy
3. **旧数据存档**：把服务器上的 `data/` 打包留一份，确认不再需要后再删
4. **公开代码仓库之前，先检查 git 历史里有没有词库数据**：
   ```bash
   git log --all --oneline -- data data.json
   ```
   有输出说明数据进过历史，即使现在删了，公开后所有人都能翻到。处理方法二选一：
   - 用 `git filter-repo --path data --path data.json --invert-paths` 改写历史，然后强推；
   - 或者新建一个仓库，只放代码，旧仓库保持私有或删除。

   `.gitignore` 里已经排除了 `data/`。

## 卡型

| 卡型 | 正面 | 背面 | 需要的字段 |
|---|---|---|---|
| 认读 | 例句（`{{…}}` 加粗），旧卡显示单词 | 中文 · 英语 / 词族 · 出处 / 补充 | 例句或单词 |
| 产出 | 中文意图 + 可选提示 | 法语答案 · 补充 | 中文意图、法语答案 |
| 挖空 | 例句，`{{…}}` 换成空格 | 完整例句 · 中文 | 带 `{{…}}` 的例句 |

- 在笔记编辑器（复习页按 `E`，或词库里点 ✎）里选层级和要生成的卡；层级切到"核心"时默认勾上认读 + 产出
- 去掉某种卡会删除它（复习日志保留），再勾回来会恢复原来那张，进度不丢
- 产出卡复习时可以先在输入框里写出答案，揭示后和标准答案并排显示（不自动判对错）；用上了就点"用上了 +1"
- 旋转和题面切换只作用于认读卡

## 分拣（迁移后整理旧卡）

词库顶部的筛选，配合"全选"和批量操作：

| 筛选 | 含义 | 建议操作 |
|---|---|---|
| 已稳定 | 间隔超过 30 天且遗忘不超过 1 次 | 保留 |
| 待改造 | 遗忘达到阈值、已自动暂停 | 补例句、加线索，然后"恢复" |
| 待补句子 | 迁移来的旧卡，还没有例句 | 编辑补例句，补完按句子出题 |
| 核心 / 待补产出 | 核心词 / 还没有产出卡的核心词 | 编辑补中文意图和答案，勾上"产出" |
| 全部 + 手动勾选 | 一眼就懂的英法同源词 | 批量"暂停" |

批量操作：旋转、设主题、移到牌组、改日期、暂停 / 恢复、设为核心 / 中频、重置为新卡、删除。

## 统计

| 指标 | 算法 | 参考 |
|---|---|---|
| 保持率 | 过去 14 天，复习状态卡评分 ≥ 2 的比例；成熟卡（作答前间隔 ≥ 21 天）和年轻卡分开 | 85%–90%。高于 95% 提示可以多加新卡，低于 80% 提示减少新卡、处理顽固卡 |
| 顽固卡 | 待改造的数量；最近 7 天又忘过的顽固卡 | 不应持续增加 |
| 今日 | 待复习、已复习、新卡已学 / 上限 | — |
| 未来 30 天到期 | 按天的柱状图（逾期算今天） | 用来判断新卡是否加太多 |
| 产出使用 | "用上了"的累计次数、最近两周新增 | — |

## 批量导入

添加 → 批量导入。每行一条笔记，字段用 `|` 分隔，后四项可省略，`#` 开头是注释：

```
Après le déménagement, les enfants ont perdu tous leurs {{repères}}. | 熟悉的参照 | bearings | InnerFrench 12 | SOCIÉTÉ
Il faut {{tenir compte de}} l'avis des habitants. | 考虑到 | take into account | | societe
```

- `{{…}}` 里的内容作为单词；主题可写多个，大小写和重音写不全也能识别，认不出来的按名称猜
- 同一牌组里句子完全相同的行自动跳过；有问题的行列出行号，不会导入
- 导入后都是中频、只有认读卡，需要产出卡的在词库里编辑
