# 🔥 VCita

单用户的间隔重复背词 Web App。纯静态站点，数据存在浏览器本地（IndexedDB），
可同步到你自己的**私有** GitHub 数据仓库的 `VCita/` 目录。同步机制与 TimeEncre 相同，两个 app 可以共用一个数据仓库。

## 功能

- **笔记 → 卡片 → 复习日志**三层结构：内容只写一次，一条笔记按需生成认读、产出、挖空三种卡；易混组里的词再各生成一张辨析卡
- **核心 / 中频**两层：核心词默认认读 + 产出两张卡，中频只认读；编辑器里实时预览三种卡
- **FSRS-6 调度**（可换回 SM-2）：按目标保持率排期，参数可以用自己的复习记录优化；四级评分、学习步骤、重学步骤、每日新卡上限、新卡穿插复习、相对逾期排序、一键分散积压、同一条笔记的卡当天只出一张；负荷预测比较不同的每日新卡数
- **常用词先学**：新卡同一层里按 Lexique 词频从高到低出
- **阴阳性**：卡面上的名词按阴阳性加下划线颜色，悬停看另一个性的形式和词尾规则（带可靠度和例外）
- **Wiktionnaire 离线数据**：近音词、同音词、同义词、词族和词源原文做成随站点发布的索引，给易混组、表达群、词族线索、词源四处提供候选（只是建议，点一下才生效）
- **产出卡逐词对照**：写出的答案和标准答案逐词比较，重音、阴阳性错误单独标出
- **顽固卡**：遗忘达到阈值（默认 8 次）自动暂停，进入"待改造"
- **输入即翻译**：回车立即入库，后台用 Google 翻译填两种目标语言，可以连续输入
- **卡片旋转**和**题面切换**：每张卡可以单独旋转题面；复习页顶部可以整体切换用哪种语言出题
- **撤销 + 全键盘操作**
- **统计**：保持率（年轻 / 成熟分开，按卡型、主题拆开）、作答用时、顽固卡、未来 30 天到期量、产出使用次数
- **分拣**：词库里按已稳定、待改造、待补句子、核心、待补产出、近 7 天忘过、难记、疑似重复、题面有误、可能易混、易混组、表达群、群里没想起筛选，可按遗忘 / 难度 / 到期 / 词频排序，配合批量操作
- **例句 / 场景轮换**：笔记可以有备用例句和备用产出题，认读、挖空、产出卡按复习次数轮换，记住的是词本身而不是某个句子
- **发音 / 听力认读**：复习页一个"发音"开关（关 / 自动读 / 听·核心词 / 听·全部）。只自动读法语，中文题面和挖空翻面后读法语答案；"听"档的认读卡正面只播放句子，R 重听
- **挖空内联提示**：`{{答案::提示}}`，横线处显示提示（优先于笔记的挖空提示）
- **自定义学习**：用词库的筛选结果临时开一轮（Anki 的筛选牌组）
- **批量导入**：每行一条，`句子（含 {{…}}）| 中文 | 英语 | 出处 | 主题`
- **8 个主题**：TRAVAIL · SOCIÉTÉ · TECHNOLOGIE · ENVIRONNEMENT · MÉDIAS · ÉDUCATION · SANTÉ · GÉNÉRAL
- **GitHub 同步**：每次同步一个提交，多设备按"较新者胜出"合并；没有改动不产生提交
- 发音走 Google TTS；部署在 CF Pages / Vercel 时随站点发布一个同源代理，不可用时退回浏览器自带语音（只用对应语言的声音，没有就不读）。刷新后浏览器不允许自动播放，自动发音会等第一次按键或点击时再播

## 部署

这是需要**构建**的 Vite 项目：源码（`src/*.tsx`）不能直接发布，必须先 `npm run build`，再发布产物目录 `dist/`。
构建命令或输出目录留空，平台会把源码原样发布，页面是空白，Console 里报
`Failed to load module script ... MIME type of "application/octet-stream"`。

纯静态，不需要任何环境变量。`base: './'` + hash 路由，部署在根路径或子路径都能用。
`.node-version` 指定了 Node 22（Vite 8 需要 Node 20.19+ / 22.12+），两个平台都会读取。

两个平台都会在你推送到 `master` 时自动重新部署。

### Cloudflare Pages

1. Dashboard → **Workers & Pages** → **Create application** → **Pages** → **Connect to Git**，选择本仓库
2. **Set up builds and deployments** 页面：

   | 项目 | 填写 |
   |---|---|
   | Production branch | `master` |
   | Framework preset | `None`（或 `Vite`，效果一样，下面两项以手填为准） |
   | Build command | `npm run build` |
   | Build output directory | `dist` |
   | Root directory (advanced) | 留空。**只有**项目文件不在仓库根目录、而是在子目录（比如 `vcita/`）时，填这个子目录 |
   | Environment variables | 不需要。如果构建日志提示 Node 版本过低，加 `NODE_VERSION` = `22` |

3. **Save and Deploy**。构建日志里应该能看到 `vite build` 和 `✓ built in …`
4. 打开 `https://<项目名>.pages.dev`，应该看到"第一次打开"的三选一页面

`functions/api/tts.js` 会自动发布为 Pages Function（发音代理），不需要额外设置。

**已经用错误配置部署过**：项目 → **Settings** → **Builds & deployments** → **Build configuration** → **Edit**，按上表改好，
然后到 **Deployments**，对最新一次点 **⋯ → Retry deployment**。

### Vercel

1. Dashboard → **Add New…** → **Project** → 导入本仓库
2. **Configure Project** 页面：

   | 项目 | 填写 |
   |---|---|
   | Framework Preset | `Vite`（一般会自动识别） |
   | Root Directory | 仓库根目录；项目在子目录时选那个子目录 |
   | Build Command | `npm run build`（展开 Build and Output Settings 确认） |
   | Output Directory | `dist` |
   | Install Command | 默认（`npm install`） |
   | Environment Variables | 不需要 |

3. **Deploy**，完成后打开 `https://<项目名>.vercel.app`

`api/tts.js` 会自动发布为 Edge Function（发音代理）。
Node 版本：项目 → **Settings** → **General** → **Node.js Version** 选 22.x（`.node-version` 通常已生效，这里确认一下）。

**改配置后重新部署**：项目 → **Settings** → **Build and Deployment** 改好后，到 **Deployments**，对最新一次点 **⋯ → Redeploy**。

## 连接 GitHub 数据仓库

1. 建一个**私有**仓库（公开仓库会被拒绝），或者直接用 TimeEncre 的数据仓库。VCita 只读写其中的数据目录（默认 `VCita/`）。
2. 生成 **fine-grained personal access token**：Repository access 只选这个仓库，Permissions 只开 `Contents: Read and write`，设置过期时间。不要用 classic token。
3. 打开 app → 设置 → GitHub 同步，填仓库（`owner/repo` 或完整网址）、数据目录和令牌，点"检查并保存"。
4. 打开"自动同步"：打开 app 时、停止改动 3 分钟后、切到后台时、一轮复习结束时各同步一次。

⚠️ fine-grained token 只能限定到仓库、不能限定到目录：和 TimeEncre 共用仓库时，两个 app 的令牌都能读写对方的数据。
令牌保存在各设备浏览器本地，不会随备份导出；"清空本地数据"会保留它。

**备份**（设置 → 数据，设置页最上面）：导入备份（选文件或把 JSON 拖进虚线框）/ **从剪贴板导入** / 导出备份（复制了备份 JSON 后直接点；剪贴板读不到或内容不是备份时只弹一条提示）。导入按"较新者胜出"逐条合并，可以重复导入。导出有两种：**.json.gz**（gzip 压缩，约为原来的十分之一）和 **JSON**（不压缩）；两种都不缩进，和默认值相同的字段（null、false、0、空串、空列表）不写，导入时自动补回。导入时两种文件都能直接选。GitHub 同步的文件格式不受影响。

**一次同步做了什么**（请求数与文件数无关，除了第 2 步）：

1. 读远端分支头和数据目录的文件列表（2–3 个请求）
2. 下载远端变过的文件：**8 个并发**。日常同步一般只有 1–3 个文件；新设备第一次同步要下载全部文件（几十个），几秒完成
3. 在一个事务里合并进本地（界面只刷新一次），计算本地变过的文件：每个文件按"里面所有对象的 id + 修改时间"做签名，签名没变就直接用上次的序列化结果和 SHA，只有真正变了的文件才重新序列化
4. 把所有变过的文件放进**一个提交**推上去（3 个请求：建树、建提交、移动分支）。没有变化就不提交

右上角的"N 个文件待同步"全局只算一份，用的是同一套缓存；连续作答时在最后一次改动 0.4 秒后才算，不会每答一张就把整个词库重新序列化一遍。

本地还没有任何数据时不会推送任何东西，所以新设备连接后不会往仓库里写一个空牌组。

## 复习算法

默认用 **FSRS-6**（Anki 23.10 起的默认算法，公式同 [fsrs-rs](https://github.com/open-spaced-repetition/fsrs-rs)，实现在 `src/srs/fsrs.ts`，测试对照 fsrs-rs 的结果）；设置 → 记忆算法 可以换回 SM-2。

### FSRS

- 每张卡有**稳定性** S（过 S 天记住的概率降到 90%）和**难度** D（1–10）。作答后按评分和"距上次复习多少个学习日"更新；同一天里的复习（学习步骤）用短期公式
- 复习卡的间隔 = 记住的概率降到**目标保持率**（默认 90%，设置里 70%–99%）的那一天；困难 ≤ 良好 < 容易。逾期多久已经在记忆模型里了，不另加逾期加成
- 学习步骤（默认 10 分钟、1 天）和重学步骤（默认 10 分钟）照常走；毕业间隔、重学后的间隔都由 FSRS 给，不用"毕业间隔""倍率"这些 SM-2 参数
- **记忆状态不存在卡片上**：每次从这张卡的复习日志重放出来。所以切换算法、换参数都不改任何数据，同步也不会多出改动；撤销的日志（墓碑）不算。日志不完整的老卡（第一条日志不是从新卡开始，或者一条日志都没有）从当时的 SM-2 间隔和倍率换算初始状态（同 fsrs-rs 的 `memory_state_from_sm2`）
- **参数**：默认是 FSRS-6 的默认参数。用自己的复习记录优化出来的参数预测更准：把导出的备份交给 Claude，用 fsrs-rs 优化后把 21 个数粘贴到 设置 → 记忆算法 → FSRS 参数（Anki 里复制的也能用）
- 卡片标签显示"记住 xx%"（现在还记得的概率）和"难度"；词库的"难记"筛选和"最难记"排序在 FSRS 下按难度
- **负荷预测**（设置 → 每日）：按 FSRS 模拟未来 30 天，比较每天不同新卡数时平均每天要复习多少次、最多的一天、大约用时（按自己的作答用时中位数）、待学新卡多少天学完

### SM-2

| 评分 | 新卡 / 学习中 | 复习卡 |
|---|---|---|
| 1 忘了 | 回到第一个学习步骤（10 分钟） | 遗忘 +1，倍率 −0.2，进入重学（10 分钟），之后间隔 = 原间隔 × 0.5（最少 1 天） |
| 2 困难 | 重复当前步骤 | 间隔 × 1.2，倍率 −0.15 |
| 3 良好 | 下一个学习步骤；走完后毕业，间隔 3 天 | 间隔 × 倍率 |
| 4 容易 | 直接毕业，间隔 4 天 | 间隔 × 倍率 × 1.3，倍率 +0.15 |

- 倍率（ease）初始 2.5，最低 1.3，越低说明越难记
- 1 天以上的步骤和所有复习间隔都对齐到**学习日**开始（默认凌晨 4 点切换），凌晨复习仍算前一天
- 间隔加随机扰动（默认 ±5%，幅度可以改，填 0 关闭；3 天以下的间隔不扰动），避免同一天加的卡永远挤在同一天到期
- **逾期加成**：复习卡逾期 d 天后答对，按 Anki 的方式把逾期算进去——困难用 (间隔 + d/4) × 1.2、良好用 (间隔 + d/2) × 倍率、容易用 (间隔 + d) × 倍率 × 1.3；但每个按钮因逾期多出来的天数最多 **30 天**（`逾期加成上限`，0 = 不加成）。例：间隔 1 天、倍率 1.9、逾期 158 天的卡点良好 → 3 + 30 = 33 天，而不是 152 天
- 出题顺序：到期的学习 / 重学卡最先 → 到期的复习卡与新卡
  - `新卡出现时机`：**穿插**（默认，Anki 的 Mix with reviews）= 新卡按"今天新卡总数 : 复习总数"的比例均匀插在复习中，复习积压时新卡也照常出；**复习完再出** = 有到期复习卡时不出新卡
  - `新卡顺序`：**重点主题 → 核心 → 中频，同层常用词先出**（默认）= 设置里勾选的重点主题的新卡最先出，其次是核心（要用出来的词），最后中频；同一层里按词频从高到低；**常用词先出（不分层）** = 重点主题之后只按词频；**按添加时间** = 先加的先出
    - 词频：[Lexique 3.83](http://www.lexique.org) 的原形词频（法语电影字幕和书籍的平均，每百万词出现次数）。短语取其中最不常用的那个实词（`écoper d'une amende` 看 écoper），qqch、括号里的说明不算；查不到的排在同一层最后。词库里每条笔记显示"频 N"，可按"最常用"排序
    - 依据：词汇覆盖率研究（Nation）——最常用的几千个词覆盖了日常文本的绝大部分，先学常用词每张卡的回报最高
  - `新卡额度拆分`：**按来源**（默认）= 每日新卡上限的 `freshShare`%（默认 60%）留给**挖矿卡**（从自己的输入里摘的，语境越新越好记），挖矿卡里最新添加的先出；其余额度按`新卡顺序`消化**词表卡**（批量导入的）；**按添加时间** = 最近 `freshDays` 天（默认 7）添加的卡占这份额度、越新越先，更早的按`新卡顺序`；**不拆分** = 只按`新卡顺序`。一份用不完的额度让给另一份；出卡顺序：新鲜份额 → 其余份额 → 互相让出的部分
    - 来源：笔记的 `origin`（`mined` / `list`）。添加页的"来源"开关（记住上次的选择）、批量导入（默认词表）、编辑笔记里设置；词库可按来源筛选、批量设为挖矿 / 词表。没标过（`null`）的按出处推断：填了出处算挖矿，没填算词表
  - `复习卡顺序`：**相对逾期**（默认）= 逾期时长 ÷ 间隔从大到小，最可能已忘的先出（设了每日复习上限时，被截掉的是最不危险的；被截掉的张数在复习页显示为"超出上限"。语言学习建议复习不设上限，用新卡数量控制负担）；**按到期时间** = 最早到期的先出
  - 同一条笔记的卡当天只出一张；没有别的卡时，20 分钟内到期的学习卡提前出（刚答完的那张除外，否则只剩它时点"困难"会立刻又出来；这时页面显示到期时间和"现在就提前复习"按钮）
- **分散积压**（设置 → 每日）：把今天之前就到期的复习卡一次性均匀改到"今天起 N 天"内到期（相当于 Anki 的"设置到期日"填一个范围）。遗忘次数多、倍率低、相对逾期大的排在前面；只改到期日，不改间隔和倍率，会随同步生效

参数分在 **设置 → 每日 / 出卡顺序 / 记忆算法** 三组里，改了立刻生效，随 GitHub 同步到其他设备。每一项的说明末尾写着默认值；每组右上角的「恢复默认」先列出会改哪些项，确认后才改（每日切换时间、时区和自己优化的 FSRS 参数不会被恢复）。

## 快捷键（复习页）

| 键 | 作用 |
|---|---|
| `空格` / `回车` | 显示答案；已显示时 = 良好 |
| `1` – `4` | 评分 |
| `U` | 撤销上一次评分 |
| `S` | 跳过（本轮不再出现） |
| `P` | 暂停这张卡（词库"已暂停"里可恢复） |
| `E` | 就地编辑这条笔记（弹窗） |
| `H` | 产出卡：显示首字母提示（默认收起，想不出来再看） |
| `L` | 跳到词库（卡片右上角"✎ 词库"），只显示这条笔记并打开编辑；顶部"返回复习" |
| `?` | 说明 |

快捷键在捕获阶段处理，不会被"空格 = 播放/暂停"类浏览器扩展抢走；输入框和弹窗里不生效。

## 数据格式

全部是 JSON。时间为带时区的 ISO 8601（毫秒），id 为 UUIDv7（迁移来的数据沿用旧 id 加前缀）。
每个文件都有 `schemaVersion`（当前为 2），读取时经 `src/schema/index.ts` 的迁移链升级到当前版本；
遇到比程序新的版本会拒绝写入。结构定义见 `src/schema/v2.ts`。

## 卡型

| 卡型 | 正面 | 背面 | 需要的字段 |
|---|---|---|---|
| 认读 | 例句（`{{…}}` 加粗），旧卡显示单词 | 中文 · 英语 / 词族 · 出处 / 补充 | 例句或单词 |
| 产出 | 法语题面（高亮一个更简单的说法，换成目标表达）；旧卡是中文意图 | 法语答案（高亮目标表达）· 中文注释 · 补充 | 法语题面（或中文意图）、法语答案 |
| 挖空 | 例句（轮换），标出的部分换成横线；横线处显示这句的挖空提示（如 `[飞越]`），没写提示时正面另显示中文意思 | 完整例句 · 中文 | 至少一句标出表达的例句 |
| 辨析 | 例句挖掉考查部分，下面列出易混组里的几个词，选用哪个 | 答案句 · 组里每个词的意思和辨析说明 | 在易混组里、带 `{{…}}` 的例句 |

### 辨析卡（易混组）

相似的记忆互相干扰是遗忘的主要原因之一（干扰理论）；把容易混的词放在一起比，比分开记更有效。

- 词库 → **可能易混**：自动找出意思相近（中文意思里有同一个不常见的词，如都有"染上色彩"）或拼写只差一个字母（amende / amande、ressembler / rassembler）的两两一对，排在一起；同词族（constater / constatation）不算
- 勾选两到五条 → **设为易混组**：每条笔记生成一张辨析卡（没有带 `{{…}}` 例句的跳过）。勾选的笔记已经在别的组里时，整组并进来
- 编辑笔记里写**辨析说明**（这个词和组里其他词的区别），辨析卡背面显示；"移出易混组"删掉这张辨析卡（复习记录保留），组里只剩一条时整组解散
- 同一个易混组的辨析卡当天只出一张；评分：选对、说得出为什么 → 良好；选对但靠猜 → 困难；选错 → 忘了
- 词库 → **易混组**：已经设好的组，同组排在一起

### 考查部分 = 词条

一条笔记只考它的词条。例句里 `{{…}}` 标的就是词条在这句话里的样子：认读卡高亮它，挖空卡挖掉它，提示（词条的意思）也是针对它的。

- **主例句标整个表达**：`Il faut que tu {{te rendes compte de}} cette vérité`，不只标 de；分开的表达标多处：`{{dénoncé}} son voisin {{à la police}}`
- **只想练小词**（介词、代词）就放进挖空例句或备用例句：`Je vais {{te}} renseigner`（renseigner qqn）、`j'ai dû {{y}} renoncer`（renoncer à qqch）——这些仍是词条的一部分
- **别的易错点不能当考查部分**：笔记的补充里记着"你写过 des certains métiers"，不等于可以出一句 `{{Certains}} métiers…`。这种写进补充，或者单独做一条笔记
- 编辑笔记里违反时会提示（不拦保存）；词库 → **题面有误** 能筛出来

### 表达群

同一个功能的几种说法（说「很多」：`nombre de` / `l'écrasante majorité de` / `un déluge de`；惊呆了：`figé` / `stupéfait` / `médusé`）放进同一个**表达群**，复习其中一条时顺带回想其他几条，养成「这个意思法语有几种说法」的习惯。

- 笔记的 `cluster` 字段就是群名（可选字段，旧的同步文件不受影响）。编辑笔记里填「表达群」（下拉里有已有的群名），或词库里勾选几条 → **设表达群**（留空 = 移出）
- 复习时背面（作答前不显示）只写「还有 N 种说法你学过（另有 M 种还没学）」，**不给意思、不给首字母**，纯回忆——从功能直接想出说法，正是写作时要的那种回忆，比产出卡（有简单说法当题面）还难
- 点「看答案」就算做了这次回想，列出学过的成员（最多 6 条），每行先是淡红虚线「没想起 → 明天再练」（还没生效）。**只点想起来的**，一下：
  - **点了（绿）**：立即给产出卡（没有在复习中的产出卡就用认读卡）记一次隐性「困难」，只往后推、不提前，今天已复习过就不动；旁边显示变化（"产出卡 5天后 → 10天后"）。再点一下撤回。按困难而不是良好：这是自评、不是正式出卡，保守一点
  - **没点（红）**：翻到下一张卡时才生效——同一张卡提前到明天到期（明天前本来就到期的不动），**不写复习记录**，旧记录也不改：FSRS 只看到明天那次正常复习，按真实结果评分。笔记上记下日期（`recallMisses`，最近 10 次），行尾会显示"之前没想起 N 次"
  - 不点「看答案」什么都不记
- 还没开始学的成员只显示意思和"还没学"，不算进 N，不考
- 词库 → **表达群**：同群排在一起；**群里没想起**：点过"没想起来"的，最近的排前面

### 阴阳性

- 名词加下划线：阳性蓝、阴性红。设置 → 卡片与添加 → **阴阳性下划线** 选显示方式：
  - **只标考查部分**（默认）：只有 `{{…}}` 考查部分里的名词画线，句子其余部分不画，注意力留在要学的词上
  - **所有名词**：卡面和词库例句里的名词都画线（线更细更淡）
  - **悬停时显示**：鼠标移到名词上才出现
  - **关闭**：不画线
  - 四种都能悬停（手机上点一下）看迷你条；以前关掉过旧的"名词按阴阳性着色"开关的，默认是关闭
- 鼠标悬停名词或形容词（手机上点一下）弹出迷你条：`un / une` + 词；另一个性的形式（acteur ↔ actrice、beau ↔ belle）；按词尾的记忆规则，带**可靠度**（Lexique 里常用名词有多少符合）和**最常见的例外**，这个词本身是例外时标 ⚠；同形异义词（le tour / la tour）给两个意思，前面有冠词时突出这里用的那个；gens、amour、délice 这类特殊词单独说明
- 也是动词变位的名词（approche、marche、demande、reste）同样能看：词典第 7 列记 `v`，只用于阴阳性，原形、词频、划词照旧按动词算；前面是主语 / 宾语代词、ne、c'est 或助动词时（il approche、j'ai été）按动词处理，不标
- 规则表在 `src/lib/gender/rules.ts`（词尾、例词、记忆提示、同形异义词），可靠度和例外由 `scripts/build-fr-dict.mjs` 从词典数据算出写进 `stats.gen.ts`。例：-tion 100%、-ment 100%、-age 98%（例外 image、plage、cage）、-ure 95%、-té 79%（例外 côté、été）、-eur 只有 64%（la peur / le moteur 两性都多，要单独记）
- 词典数据：Lexique 3.83（词频、词性、大部分名词的性）+ Lefff 3.4（补 Lexique 没标性别的名词，如 main、maison、voiture），生成 `src/lib/gender/fr-dict.txt`（约 2.6 MB，压缩后约 0.5 MB），第一次用到时才下载，文件名带哈希，浏览器长期缓存
  - 重新生成：`node scripts/build-fr-dict.mjs <Lexique383.txt> <lefff-3.4.mlex>`（原始文件不进仓库；Lexique383.txt 在 PyPI 的 pylexique 包里，Lefff 在 FrenchLefffLemmatizer 仓库里）
  - 许可：Lexique 3 是 CC BY-SA 4.0（New, Pallier, Brysbaert & Ferrand），Lefff 是 LGPL-LR（Sagot）。`fr-dict.txt` 是它们的衍生数据，沿用这两个许可

- **新建**（"添加"页）和**修改**（复习页按 `E`，或词库里点 ✎）用同一张表单，代码在 `src/features/noteform/`：
  - **表达**：考什么只写这一次（`prendre qqn dans le sens du poil`）。最快的用法是写表达、回车，生成一张认读卡，意思在后台翻译
  - **例句表**：例句直接写普通句子，程序按表达自动标出考查部分（`src/lib/markTarget.ts`：法语用词典 + 变位表还原词形，代动词的 `me suis`、被隔开的 `se rend … compte de` 都认得），标错了点词改；改了表达，没手动点过的句子自动重标。第一句是主句，用 ↑ 调顺序
  - 没写"换说法"的句子给认读、挖空、辨析用（每次复习轮换）；写了**换说法**的句子是一道**产出题**：正面把标出的部分换成换说法（不能用答案里的词），产出题的答案句不进认读轮换。表达分成几段、换说法替换不了时点"整句手写题面"
  - 每句例句下面可以写这句的**挖空提示**（横线处显示的意思，相当于 Anki 的 `{{c1::survoler::飞越}}`）；没写时正面显示中文意思，只挖小词时不给提示。存进数据库时第一句的提示是 `clozeHint`，其他句写成 `{{答案::提示}}`
  - **卡片**区：认读 / 挖空 / 产出的开关，每种写着用了哪几句、还缺什么；在易混组里的笔记多一张辨析卡（跟着组走）；下面分页预览每种卡的正反面，"下一句"看轮换到的其他句子
  - **用法**（可选）：这张卡考的结构 + 意思，同义的其他结构也写上，所有卡的背面都显示（`用法 · s'occuper de + 名词 / + inf.：负责、照料（⚠ 不用 à）`）。介词、语式是表达的一部分时，例句里的标记连介词一起标（`je {{m'occupe des}} billets`），产出题的换说法也不要白送同一个介词
  - **背面补充**（词源、词族、补充、出处）和**归类**（层级、来源、主题、牌组、日期）默认收起
  - 存储格式没变：表单只是换了编辑方式，保存时写回 `sentence`、`altSentences`、`promptFr` / `answerFr` / `altIntents` 等字段。老笔记单独的"挖空例句"打开编辑后并进例句表（它的提示跟着那句走），一模一样的备用产出题合并成一道
  - 设置 → 界面 → **挖空卡横线处显示首字母和字母数**（默认关）：`[飞越] s _ _ _ _ _ _ _`，适合中文提示对应好几个近义词时
- 去掉某种卡会删除它（复习日志保留），再勾回来会恢复原来那张，进度不丢
- 产出卡复习时可以先在输入框里写出答案，揭示后**逐词对照**（不自动判对错）：一样的绿色，你写的删除线、答案波浪下划线，只差重音、阴阳性写错（le / la、un / une、grand / grande）单独标出；只写了要换的部分就只和高亮部分比，写了整句就和整句比。首字母提示（H）由答案句自动生成：句子其余部分照常显示，只有要产出的部分给首字母（`L'enfance t… toute notre vie.`），笔记里的"提示"只用于没有法语题面的老卡。用上了就点"用上了 +1"
- 旋转和题面切换只作用于认读卡


### Wiktionnaire 离线数据

Wiktionnaire 里的近音词（paronymes）、同音词（homophones）、同义词（synonymes）、词族（dérivés / apparentés）和词源原文，做成两份随站点发布的索引。只读、只给候选：不新增卡型和页面，不改存储格式，写进去的都是已有字段。

- **可能易混**（词库筛选）多两种理由，排在最前面：库里两条笔记互为近音词 → `近音：éminent / imminent`；互为同音词 → `同音：ver / verre`。拼写差得远的（conjecture / conjoncture）、很短的词（cou / coup / coût）以前都找不出来。照旧选中后「设为易混组」才生成辨析卡
- **表达群**（词库筛选）上方列出「可以并成一群」：库里两条笔记互为同义词、又不在同一个群里。点一下就加入：一边已经在群里，另一边并进去；都不在就新起一个群，名字取中文意思的第一个词（说「惊呆的」），之后可以用「设表达群」改名或移出。两边各有各的群时不建议
- **词族线索**（笔记表单 → 背面补充）下方列出词族候选，库里已有的排前面（实线），其次按词频。点一个填进词族线索（库里有的带上它的中文意思，条目之间用 `；` 分开），再点一次去掉
- **词源**（笔记表单 → 背面补充）下方小字显示 Wiktionnaire 的词源原文（法语），只作参考、**不自动填**：`etymology` 字段是你写的中文讲解
- 多词表达按第一个实词查（`prendre qqn dans le sens du poil` → prendre、`s'occuper de` → occuper）。非法语牌组、索引没下载到时，四处都和没有这份数据时一样
- 数据文件在 `src/lib/wikt/`，都是第一次用到时才下载（首屏不下载），文件名带哈希，浏览器长期缓存：
  - `fr-links.txt`：`原形 \t 近音 \t 同音 \t 同义 \t 词族`，各列用 `,` 分隔（目标 ≤ 1.5 MB）。点到「可能易混」「表达群」筛选，或展开笔记表单的「背面补充」时下载
  - `fr-etym.txt`：`原形 \t 词源原文`，取第一条、截到 300 字符（目标 ≤ 3 MB）。只有展开笔记表单的「背面补充」时下载
  - 只收 `fr-dict.txt` 里词频大于 0 的原形；链接词只留词典里有的，按词频从高到低，每类最多 8 个；关系补成双向（Wiktionnaire 常常只有一边写了）；超过目标大小时从词频最低的原形开始丢
- 重新生成（原始文件不进仓库；流式读取，不解压到磁盘。传网址时边下载边处理，700 MB 的压缩包也不落盘）：

  ```
  node scripts/build-fr-wikt.mjs https://kaikki.org/dictionary/downloads/fr/fr-extract.jsonl.gz
  ```

  也可以先下载再传路径：`node scripts/build-fr-wikt.mjs fr-extract.jsonl.gz`。跑完会打印两个文件的大小、词频前 5000 / 20000 的原形里各列非空的比例，以及几组验收词对（éminent / imminent、ver / verre / vert / vers、seau / sceau / sot / saut…）找没找到
- 来源和许可：[kaikki.org](https://kaikki.org/dictionary/rawdata.html) 的法语维基词典提取（`fr-extract.jsonl.gz`，由 [wiktextract](https://github.com/tatuylonen/wiktextract) 生成，大约每周更新）。内容来自 Wiktionnaire（fr.wiktionary.org），CC BY-SA 4.0；`fr-links.txt`、`fr-etym.txt` 是它的衍生数据，沿用这个许可

## 分拣（迁移后整理旧卡）

词库顶部的筛选，配合"全选"和批量操作：

| 筛选 | 含义 | 建议操作 |
|---|---|---|
| 已稳定 | 间隔超过 30 天且遗忘不超过 1 次 | 保留 |
| 待改造 | 遗忘达到阈值、已自动暂停 | 补例句、加线索，然后"恢复" |
| 待补句子 | 迁移来的旧卡，还没有例句 | 编辑补例句，补完按句子出题 |
| 核心 / 待补产出 | 核心词 / 还没有产出卡的核心词 | 编辑补中文意图和答案，勾上"产出" |
| 全部 + 手动勾选 | 一眼就懂的英法同源词 | 批量"暂停" |
| 近 7 天忘过 | 最近 7 个学习日里评过"忘了" | 展开看是哪种卡忘的；改句子、加线索、填挖空提示 |
| 难记 | FSRS：有卡的难度 ≥ 7；SM-2：倍率低于 2（常答困难 / 忘了） | 在变成顽固卡之前先改造 |
| 题面有误 | 例句标的不是词条（`{{Certains}} métiers…` 却是 un métier très féminisé 的笔记），或主例句没把整个表达标进去（se rendre compte de 只标了 de）；产出题的高亮没包住词条，或高亮直接给出了答案 | 改例句的标注 / 题面和答案的高亮范围；别的易错点写进补充或单独做一条 |
| 可能易混 / 易混组 | 见上面"辨析卡" | 设为易混组，写辨析说明 |
| 表达群 / 群里没想起 | 见上面"表达群" | 设表达群；没想起的那条多看几遍、补例句 |
| 疑似重复 | 同牌组里单词（按 , ; / 拆开的每一项）、考查部分或整句相同，或例句词汇重合 ≥ 75%；同组排在一起，标"重复组 N" | 删除或暂停多余的一条（`se poursuivre` 和 `poursuivre` 不算重复） |

**排序**（筛选栏最右）：最新添加 / 遗忘最多 / 最难记 / 最早到期 / 最近复习 / 最常用（词频），按这条笔记里最差的那张卡算。

**展开**（每行的 ▾）：分别显示认读、产出、挖空每张卡的状态、复习次数、忘了几次和最近 20 次评分（红 = 忘了、黄 = 困难、绿 = 良好、蓝 = 容易），下面是最近 50 次复习记录（时间、卡型、评分、间隔变化、倍率变化）。

**自定义学习**（"学这 N 条"）：用当前筛选结果开一轮，有勾选时只用勾选的笔记。可以选卡型、最多几张、是否打乱。
- 本来就到期的卡照常调度、记入复习；没到期的卡和新卡**只练习**，不改变复习安排
- 忘了 → 隔 3 张再出；困难 → 本轮最后；良好 / 容易 → 本轮完成；可以撤销
- 同一条笔记的卡至少隔 3 张再出（不会刚看完产出卡的答案就考挖空）；只剩兄弟卡时才连着出
- 复习页顶部显示进度，点"结束"回到正常复习；刷新页面不丢，关掉标签页就结束
- 用法举例：写作前筛主题 TRAVAIL 只练产出卡；筛"近 7 天忘过"再过一遍

批量操作：旋转、设主题、移到牌组、改日期、暂停 / 恢复、设为核心 / 中频、设为挖矿 / 词表、重置为新卡、删除。

## 批量导入

添加 → 批量导入。每行一条笔记，字段用 `|` 分隔，后四项可省略，`#` 开头是注释：

```
Après le déménagement, les enfants ont perdu tous leurs {{repères}}. | 熟悉的参照 | bearings | InnerFrench 12 | SOCIÉTÉ
Il faut {{tenir compte de}} l'avis des habitants. | 考虑到 | take into account | | societe
```

- `{{…}}` 里的内容作为单词；主题可写多个，大小写和重音写不全也能识别，认不出来的按名称猜
- 同一牌组里句子完全相同的行自动跳过；有问题的行列出行号，不会导入
- 导入后都是中频、只有认读卡，需要产出卡的在词库里编辑
